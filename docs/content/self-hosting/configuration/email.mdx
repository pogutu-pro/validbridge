# Email Configuration

ValidBridge supports two email providers for transactional email delivery: **Resend** and **SMTP**. Email is used for user invitations, password resets, and system notifications.

## Choosing a Provider

Set the email provider in your `.env` file using the `VALIDBRIDGE_EMAIL_PROVIDER` variable:

```env
VALIDBRIDGE_EMAIL_PROVIDER=resend   # or "smtp"
```

## Option 1: Resend

[Resend](https://resend.com) is a developer-friendly email API service.

```env
VALIDBRIDGE_EMAIL_PROVIDER=resend
VALIDBRIDGE_RESEND_API_KEY=re_your-resend-api-key
VALIDBRIDGE_SYSTEM_EMAIL_ADDRESS=noreply@example.com
```

### Getting a Resend API Key

1. Create an account at [resend.com](https://resend.com)
2. Add and verify your sending domain
3. Generate an API key from the Resend dashboard
4. Copy the API key into your `.env` file

## Option 2: SMTP

You can use any SMTP server, including services like Amazon SES, Mailgun, or your own mail server.

```env
VALIDBRIDGE_EMAIL_PROVIDER=smtp
VALIDBRIDGE_SMTP_HOST=smtp.example.com
VALIDBRIDGE_SMTP_PORT=587
VALIDBRIDGE_SMTP_USERNAME=user@example.com
VALIDBRIDGE_SMTP_PASSWORD=your-smtp-password
VALIDBRIDGE_SMTP_USE_TLS=true
VALIDBRIDGE_SYSTEM_EMAIL_ADDRESS=noreply@example.com
```

### SMTP Variables

| Variable | Description | Default |
|---|---|---|
| `VALIDBRIDGE_SMTP_HOST` | SMTP server hostname | -- |
| `VALIDBRIDGE_SMTP_PORT` | SMTP server port | `587` |
| `VALIDBRIDGE_SMTP_USERNAME` | SMTP authentication username | -- |
| `VALIDBRIDGE_SMTP_PASSWORD` | SMTP authentication password | -- |
| `VALIDBRIDGE_SMTP_USE_TLS` | Enable TLS encryption | `true` |

## Applying Changes

After updating your email configuration, restart your instance:

```bash
validbridge stop
validbridge start
```

## System Email Address

The `VALIDBRIDGE_SYSTEM_EMAIL_ADDRESS` is the "from" address used for all outgoing emails. When using Resend, this address must belong to a domain that is verified in your Resend account. When using SMTP, ensure the address is permitted by your SMTP server.

## Sender Display Name

Emails arrive as `ValidBridge <noreply@example.com>`. `VALIDBRIDGE_SYSTEM_EMAIL_SENDER_NAME` replaces the `ValidBridge` part for the whole deployment:

```env
VALIDBRIDGE_SYSTEM_EMAIL_SENDER_NAME=Acme Academy
```

It defaults to `ValidBridge`, so leaving it unset changes nothing.

### Per-organization override

Organization administrators can set their own name under **Dashboard → Organization → Settings → General → Email Sender Name**. Mail sent for that organization (invitations, password resets, verification, role changes, welcome mail, lifecycle nudges) then carries the organization's name instead of the deployment default. Mail that is not about a single organization — platform password resets, org-less signups, account deletion, magic-login links — always uses the deployment default.

<Callout type="info">
Only the display **name** is configurable, never the sending **address**. The address stays `VALIDBRIDGE_SYSTEM_EMAIL_ADDRESS`, which is the domain carrying your verified SPF and DKIM records. An organization sending from an address on some other domain would fail DKIM alignment on every message, and on a shared sending domain that damages deliverability for every other tenant too.
</Callout>

Names are sanitized before they reach the header: control characters and line breaks are removed, whitespace runs are collapsed, and the result is capped at 64 characters. A carriage return or newline in a header value is header injection, so this is enforced on write and again on send.

<Callout type="info">
If email is not configured, features like user invitations and password resets will not work. Users can still be created manually by an administrator.
</Callout>

## What Emails Are Sent

ValidBridge sends the following types of email:

- **User invitations** -- when an admin invites a user to join the platform or an organization
- **Password resets** -- when a user requests a password reset
- **System notifications** -- important system-level notifications
