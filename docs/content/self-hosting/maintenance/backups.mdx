# Backups

Regular backups are essential for protecting your ValidBridge data. This guide covers backing up and restoring the PostgreSQL database using Docker Compose.

<Callout type="warning">
The database backup only covers the database and your `.env` file. Uploaded content (images, videos, documents) stored on the filesystem is **not** included. See [Filesystem Content](#filesystem-content) below for recommendations.
</Callout>

## Creating a Backup

Create a database dump with `pg_dump`:

```bash
docker compose exec db pg_dump -U validbridge validbridge > backup-$(date +%Y%m%d%H%M%S).sql
```

This creates a SQL dump of the ValidBridge PostgreSQL database. You may also want to copy your `.env` file alongside it.

<Callout type="info">
If you use an external managed database, use that provider's native backup tools instead.
</Callout>

## Restoring from a Backup

To restore from a backup file:

```bash
cat backup-<timestamp>.sql | docker compose exec -T db psql -U validbridge validbridge
```

<Callout type="warning">
Restoring a backup overwrites the database. Make sure you are restoring to the correct instance.
</Callout>

## Automating Backups

It is recommended to set up automated backups using a cron job. For example, to create a daily backup at 2:00 AM:

```bash
# Edit your crontab
crontab -e

# Add this line for daily backups at 2 AM
0 2 * * * docker compose -f /path/to/validbridge/docker-compose.yml exec db pg_dump -U validbridge validbridge > /path/to/backups/backup-$(date +\%Y\%m\%d).sql
```

## Backup Retention

Backup files accumulate over time and can consume significant disk space. Implement a retention policy to remove old backups. For example, keep the last 7 daily backups:

```bash
find /path/to/backups -name "backup-*.sql" -mtime +7 -delete
```

## Filesystem Content

When `VALIDBRIDGE_CONTENT_DELIVERY_TYPE=filesystem`, uploaded files live on the host (or in a Docker volume) and are **not** captured by the database backup. You are responsible for backing up this directory separately — for example with `rsync`, a volume snapshot, or a scheduled `tar` job.

When using `s3api` storage, rely on your S3 provider's versioning, lifecycle, or cross-region replication features to protect uploaded content.
